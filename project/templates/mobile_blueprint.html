1. Login / Register

Two tabs on one screen. No session required.

Login

POST /auth/login/ ⓘOn success Django sets a sessionid cookie and a csrftoken cookie. Store the csrftoken and include it as X-CSRFToken on every subsequent POST/DELETE.
Request — application/x-www-form-urlencoded
email=user@example.com
password=secret
Success
HTTP 302 → /   (check redirect URL or status)
Error
HTTP 200 with error message in HTML

Register

POST /auth/register/
Request — application/x-www-form-urlencoded
email=user@example.com
password=secret
password2=secret
plan=free
Notes
Always use plan=free on signup. Upgrade via billing.

Forgot password

BROWSER https://drp.fyi/auth/forgot-password/ ⓘOpen in system browser. The full reset email + token flow is handled by Django on the web — too complex to reimplement natively.

2. Home / Upload

Main screen. Supports anonymous and authenticated users. Toggle between File and Text.

Check key availability

GET /check-key/?key=<key>&ns=<f|c> ⓘCall on every keystroke (debounced ~300ms). ns=f for file, ns=c for clipboard/text. Show a green tick or red cross inline next to the key input.
Response
{ "available": true,  "ns": "f", "key": "my-key" }
{ "available": false, "reserved": true, "ns": "f", "key": "save" }

Upload File (3-step)

File uploads go directly to Backblaze B2, not through your server. Step 1 gets a presigned PUT URL, step 2 uploads to B2, step 3 registers the drop.
POST /upload/prepare/ Step 1
Request — application/json
{
  "filename": "photo.jpg",
  "size": 1048576,
  "content_type": "image/jpeg",
  "ns": "f",
  "key": "my-key"   // optional
}
Response
{
  "presigned_url": "https://s3.backblaze.com/...",
  "key": "my-key",
  "ns": "f",
  "expires_in": 3600
}
PUT <presigned_url> Step 2 — direct to B2 ⓘNo auth headers needed. PUT raw file bytes with the correct Content-Type. Presigned URL expires in 3600s.
Request
Headers: Content-Type: image/jpeg
Body: raw file bytes
POST /upload/confirm/ Step 3
Request — application/json
{
  "key": "my-key",
  "ns": "f",
  "filename": "photo.jpg",
  "burn": false,
  "password": ""   // paid only
}
Response
{ "key": "my-key", "url": "/f/my-key/" }
// Full URL: https://drp.fyi/f/my-key/

Drop Text

POST /save/
Request — multipart/form-data
key=my-key          // optional
content=hello world
expiry_days=7       // paid only
password=secret     // paid only
Response
{ "key": "abc123", "url": "/abc123/" }
// Full URL: https://drp.fyi/abc123/

3. File Drop View

Shown after file upload or when opening a /f/<key>/ link. Shows filename and size. All actions use the /f/<key>/ prefix.

View drop metadata

GET /f/<key>/ ⓘSend Accept: application/json to get JSON. For password-protected drops include X-Drop-Password header.
Headers
Accept: application/json
X-Drop-Password: secret   // if password protected

Download

GET /f/<key>/download/ ⓘReturns a redirect to a presigned B2 download URL. Open in system browser or use a download manager.
Headers (if password protected)
X-Drop-Password: secret

Actions owner only

POST /f/<key>/rename/
Request — application/json
{ "new_key": "better-name" }
Response
{ "key": "better-name", "url": "/f/better-name/" }
DELETE /f/<key>/delete/
Response
{ "deleted": true }
POST /f/<key>/renew/ paid ⓘExtends expiry by plan's max_expiry_days from now. Only works if the drop has an expiry set.
Response
{ "expires_at": "2026-03-01T00:00:00Z", "renewals": 1 }
POST /f/<key>/copy/ paid ⓘCopies the B2 object server-side — no re-upload needed. Omit new_key for auto-generated key.
Request — application/json (optional)
{ "new_key": "my-copy" }
Response
{ "key": "my-copy", "url": "/f/my-copy/" }
POST /f/<key>/set-password/ paid
Request — application/json
{ "password": "secret" }   // set
{ "password": "" }         // remove

Bookmarks login required

POST /f/<key>/save/
Response
{ "saved": true, "created": true }
POST /f/<key>/unsave/
Response
{ "saved": false, "deleted": true }

5. My Drops

List of owned drops and bookmarks. Single API call returns both.

GET /auth/account/ ⓘSend Accept: application/json. Build full URL from ns + key: ns=="f" → /f/key/, ns=="c" → /key/
Headers
Accept: application/json
Response
{
  "drops": [
    {
      "key": "abc123",
      "ns": "c",            // "c"=text, "f"=file
      "kind": "text",       // "text" | "file"
      "created_at": "2026-02-21T00:00:00Z",
      "expires_at": "2026-03-21T00:00:00Z",  // null if none
      "filename": null,
      "filesize": null,
      "locked": false,
      "view_count": 5,
      "last_viewed_at": "2026-02-21T10:00:00Z",
      "last_accessed_at": "2026-02-21T10:00:00Z"
    }
  ],
  "saved": [
    {
      "key": "xyz",
      "ns": "f",
      "saved_at": "2026-02-20T00:00:00Z",
      "url": "/f/xyz/"
    }
  ]
}
Build full URL
ns == "f"  →  https://drp.fyi/f/<key>/
ns == "c"  →  https://drp.fyi/<key>/

Show plan cards in Account. Open browser — never implement in-app payment (Apple IAP = 30% cut).

Upgrade

BROWSER /billing/checkout/starter/

Auth & CSRF Setup

How Django session auth works with a native app.

Flow
1. POST /auth/login/ → Django sets:
     sessionid   — identifies the session
     csrftoken   — CSRF protection token

2. Store csrftoken value.

3. Every POST/DELETE must include:
     X-CSRFToken: <csrftoken value>

4. FlutterFlow: enable persistent cookie jar
   so sessionid is sent automatically.
Common headers
Cookie: sessionid=<val>; csrftoken=<val>
X-CSRFToken: <val>        // POST/DELETE only
Accept: application/json  // always
Base URL
https://drp.fyi
