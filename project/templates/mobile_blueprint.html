1. Login / Register

Two tabs on one screen. No session required.

Login

POST /auth/login/ ⓘOn success Django sets a sessionid cookie and a csrftoken cookie. Store the csrftoken and include it as X-CSRFToken on every subsequent POST/DELETE.
Request — application/x-www-form-urlencoded
email=user@example.com
password=secret
Success
HTTP 302 → /   (check redirect URL or status)
Error
HTTP 200 with error message in HTML (check for error text)

Register

POST /auth/register/
Request — application/x-www-form-urlencoded
email=user@example.com
password=secret
password2=secret
plan=free
Notes
plan: "free" | "starter" | "pro"
Always use "free" on signup — upgrade via billing.

Forgot password

BROWSER https://drp.fyi/auth/forgot-password/ ⓘOpen in system browser. Too complex to reimplement natively — the full reset email + token flow is handled by Django on the web.

2. Home / Upload

Main screen. Supports anonymous and authenticated users. Toggle between File and Text.

Check key availability

GET /check-key/?key=<key>&ns=<f|c> ⓘCall on every keystroke (debounced). ns=f for file, ns=c for clipboard/text. Show a green tick or red cross inline next to the key input.
Response
{ "available": true,  "ns": "f", "key": "my-key" }
{ "available": false, "reserved": true, "ns": "f", "key": "save" }

Upload File (3-step)

File uploads go directly to Backblaze B2, not through your server. Step 1 gets a presigned PUT URL, step 2 uploads to B2, step 3 registers the drop.
POST /upload/prepare/ Step 1
Request — application/json
{
  "filename": "photo.jpg",
  "size": 1048576,
  "content_type": "image/jpeg",
  "ns": "f",
  "key": "my-key"   // optional, omit for auto key
}
Response
{
  "presigned_url": "https://s3.backblaze.com/...",
  "key": "my-key",
  "ns": "f",
  "expires_in": 3600
}
PUT <presigned_url> Step 2 — direct to B2 ⓘNo auth headers needed. Just PUT the raw file bytes with the correct Content-Type to the presigned URL. Expires in 3600s.
Request
Headers: Content-Type: image/jpeg
Body: raw file bytes
POST /upload/confirm/ Step 3
Request — application/json
{
  "key": "my-key",
  "ns": "f",
  "filename": "photo.jpg",
  "burn": false,
  "password": ""   // paid only
}
Response
{ "key": "my-key", "url": "/f/my-key/" }
Full URL
https://drp.fyi/f/my-key/

Drop Text

POST /save/
Request — multipart/form-data
key=my-key          // optional
content=hello world
expiry_days=7       // paid only
password=secret     // paid only
Response
{ "key": "abc123", "url": "/abc123/" }
// Full URL: https://drp.fyi/abc123/

3. Drop View

Shown after upload or when opening a drop link. Two URL namespaces — file (/f/<key>/) and text (/<key>/). All actions work on both, just swap the prefix.

View drop

GET /f/<key>/  ·  /<key>/ ⓘSend Accept: application/json to get JSON instead of HTML. For password-protected drops, include X-Drop-Password: <pw> header.
Headers
Accept: application/json
X-Drop-Password: secret   // if password protected

Download file

GET /f/<key>/download/ ⓘReturns a redirect to a presigned B2 download URL. Open in system browser or use a download manager. Include X-Drop-Password header if the drop is password-protected.
Headers (if password protected)
X-Drop-Password: secret

View raw text

GET /raw/<key>/

Rename owner only

POST /f/<key>/rename/  ·  /<key>/rename/
Request — application/json
{ "new_key": "better-name" }
Response
{ "key": "better-name", "url": "/f/better-name/" }

Delete owner only

DELETE /f/<key>/delete/  ·  /<key>/delete/
Response
{ "deleted": true }

Renew owner only paid

POST /f/<key>/renew/  ·  /<key>/renew/ ⓘExtends the expiry by the plan's max_expiry_days from now. Only works if the drop has an expiry set. Returns updated expiry and renewal count.
Response
{ "expires_at": "2026-03-01T00:00:00Z", "renewals": 1 }

Copy drop paid

POST /f/<key>/copy/  ·  /<key>/copy/ ⓘDuplicates the drop under a new key. For file drops, copies the B2 object server-side — no re-upload needed. Omit new_key for an auto-generated key.
Request — application/json (optional)
{ "new_key": "my-copy" }   // omit for auto key
Response
{ "key": "my-copy", "url": "/f/my-copy/" }

Bookmark login required

POST /f/<key>/save/  ·  /<key>/save/
Response
{ "saved": true, "created": true }
POST /f/<key>/unsave/  ·  /<key>/unsave/
Response
{ "saved": false, "deleted": true }

Set / remove password owner only paid

POST /f/<key>/set-password/  ·  /<key>/set-password/
Request — application/json
{ "password": "secret" }   // set
{ "password": "" }         // remove

4. My Drops

List of owned drops and bookmarks. Single API call returns both.

GET /auth/account/ ⓘSend Accept: application/json to get JSON. Without it, returns HTML. Build the full URL from ns + key: ns=="f" → /f/key/, ns=="c" → /key/
Headers
Accept: application/json
Response
{
  "drops": [
    {
      "key": "abc123",
      "ns": "c",            // "c"=text, "f"=file
      "kind": "text",       // "text" | "file"
      "created_at": "2026-02-21T00:00:00Z",
      "expires_at": "2026-03-21T00:00:00Z",  // null if no expiry
      "filename": null,
      "filesize": null,
      "locked": false,
      "view_count": 5,
      "last_viewed_at": "2026-02-21T10:00:00Z",
      "last_accessed_at": "2026-02-21T10:00:00Z"
    }
  ],
  "saved": [
    {
      "key": "xyz",
      "ns": "f",
      "saved_at": "2026-02-20T00:00:00Z",
      "url": "/f/xyz/"
    }
  ]
}
Build full URL
ns == "f"  →  https://drp.fyi/f/<key>/
ns == "c"  →  https://drp.fyi/<key>/

6. Plans / Subscription

Show plan cards in Account. Do not implement in-app payment — Apple requires IAP for in-app purchases (30% cut). Open browser instead.

⚠️ Apple policy: you cannot charge users inside the app through your own payment processor. Open the browser to your web checkout instead. Redirecting is fully allowed.

Upgrade

BROWSER /billing/checkout/starter/
BROWSER /billing/checkout/pro/ ⓘOpens the LemonSqueezy hosted checkout. The URL passes the user's email and user_id as params so the subscription gets linked to their account automatically.

Manage / cancel subscription

BROWSER /billing/portal/ ⓘDjango redirects the logged-in user to their LemonSqueezy customer portal. The user may need to log in on the web if their browser session has expired. Consider adding a one-time token login endpoint in the future.

Auth & CSRF Setup

How Django session auth works with a native app.

How it works
1. POST /auth/login/ → Django sets two cookies:
     sessionid   — identifies the logged-in session
     csrftoken   — CSRF protection token

2. Store csrftoken value from the cookie.

3. On every POST or DELETE request, add header:
     X-CSRFToken: <csrftoken value>

4. FlutterFlow: enable persistent cookie jar on
   the HTTP client so sessionid is sent automatically.
Base URL
https://drp.fyi
Common headers for all authenticated requests
Cookie: sessionid=<value>; csrftoken=<value>
X-CSRFToken: <csrftoken value>   // POST/DELETE only
Accept: application/json          // to get JSON not HTML
