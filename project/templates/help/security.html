Security

drp is built with security-first practices to protect your data.

Your data is safe

Whether you're using drp anonymously or with a paid plan, your privacy and security are paramount. Here's how we protect you:

Access control by plan

Collections and groups are plan-aware. When you downgrade your plan, your existing data is preserved but access is restricted based on your quota. When you upgrade again, full access is immediately restored. Your data is never deleted.

  • Pro and Pro+ plans: Unlimited collections and groups
  • Starter plan: Up to 10 collections and 3 groups
  • Free plan: No collections or groups (read-only access to shared drops)

Password protection is rate-limited

Drops with password protection are defended against brute-force attacks. Maximum 10 password attempts per hour per IP address. After hitting the limit, you'll need to wait an hour before trying again.

Webhooks are validated

If you use webhooks to notify external systems when drops are created or accessed, those URLs are validated before use. We automatically reject:

  • URLs pointing to localhost or local IP addresses (127.0.0.1, 10.x.x.x, 192.168.x.x, etc.)
  • URLs containing credentials (username:password@host)
  • Protocols other than HTTP and HTTPS

This prevents SSRF attacks that could compromise your internal infrastructure.

File names are safely encoded

When you download files, the Content-Disposition header is correctly encoded according to RFC 5987. This prevents header injection attacks even if your file names contain special characters.

Passwords are hashed, not stored in plain text

Drop passwords are hashed using Django's battle-tested password hashing system (PBKDF2), not stored in plain text. Even if your account data were somehow compromised, your passwords would be unreadable.

Sessions are secure

We use Django's built-in session framework with HttpOnly and Secure flags, preventing JavaScript access and ensuring cookies are only sent over HTTPS.

Anonymous drops are pseudo-random, not sequential

Drop keys for anonymous drops are generated using cryptographically secure random functions, not sequential numbers. Every attempt to guess a key is computationally infeasible.

Inputs are validated

All user inputs are validated and sanitized. File uploads are scanned, email addresses are verified, and URLs are checked before use.

No third-party tracking or analytics

We do not run Google Analytics, Mixpanel, or similar behavioural trackers. We do not collect or sell user data for profiling or marketing. If you see ads on drp, those are powered only by Google AdSense, and you can opt out of personalized ads.

Storage is encrypted at rest

Files stored in Backblaze B2 are encrypted at rest. Access to your files is strictly controlled by presigned URLs that expire after one hour.

Best practices for you

Security is a shared responsibility. Here's what you can do:

  • Don't use anonymous drops for sensitive information. They are only protected by a hard-to-guess URL. If you need real privacy, use a password and set an expiry.
  • Use strong passwords. A simple password like "abc123" can be guessed in seconds. Aim for 12+ characters with mixed case, numbers, and symbols.
  • Set appropriate expiry times. The shorter the expiry, the less time an attacker has to exploit a compromised link.
  • Don't share drop links in plain text emails or messages. URLs are logged in email providers and message histories. Consider using a password-protected drop with a separate password delivery channel.
  • Regular security updates. Keep your OS, browser, and password manager updated to patch known vulnerabilities.

Reporting security issues

Found a security vulnerability? Please email security@{{ domain }} instead of filing a public issue. We take security seriously and will respond within 48 hours.
